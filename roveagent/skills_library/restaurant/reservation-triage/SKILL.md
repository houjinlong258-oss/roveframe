# 预约分诊

把预约列表变成「哪张台什么时候给谁」，并把冲突在客人到店前解决掉。

## 何时使用

- 每日开餐前巡检
- 老板问「今晚排得开吗」「还有没有空位」
- 出现同一桌重复预订、或超订时

## 需要的数据

1. 预约列表：时间、人数、姓名、联系方式、备注（忌口、生日、包间需求）
2. 桌位表：桌号、座位数、是否包间、可拼桌性
3. 时段容量：每时段最多可接待人数（后厨与前台的真实上限）

## 步骤

1. 按 30 分钟分桶，统计每个时段的**预订人数 vs 容量**，标出超载时段。
2. 为每条预约匹配桌型：
   - 人数 ≤ 座位数，且尽量**不留过多空位**（4 人给 8 人桌是浪费）
   - 有包间/忌口/生日等需求的优先满足
3. 检测三类问题并各自给出处理动作：
   - **冲突**：同一桌同一时段被订两次 → 给出调桌方案
   - **超订**：时段人数超过容量 → 给出「引导到相邻时段 / 拼桌 / 婉拒」的优先级
   - **空台机会**：某些时段容量未用满 → 给出可接受的散客量
4. 备注里的**特殊需求**要单独列成一张「到店前必须准备」清单（蛋糕、儿童椅、无麸质等）。

## 输出格式

- 时段容量表：时段 / 预订人数 / 容量 / 余量 / 状态
- 分桌建议表：预约人 / 时间 / 人数 / 建议桌号 / 备注要点
- 待处理清单：冲突与超订项 + 建议动作 + 需要谁去沟通

## 边界

- 桌型匹配要给**理由**，不要只给结果 —— 前台要能向客人解释。
- 联系客人改时段属于对外沟通，**先出话术草稿**，由老板或前台发出。
- 不确定的容量信息不要假设，直接说「缺每时段容量数据，无法判断是否超订」。
