# 流失客户召回

把「好久没来的客人」变成「这周回来的客人」，靠的是**逐人个性化**，不是群发模板。

## 何时使用

- 老板问「怎么让老客回来」「上个月流失了多少人」
- 出现连续 21 天以上未消费的客户
- 淡季提频

## 需要的数据

1. 客户 360：最近消费时间、累计消费、常点菜品、客单价、偏好/忌口
2. 沉默天数分布（相对本店的平均复购周期，而不是全行业平均）
3. 可用的触达渠道与频次上限（同一客户在 N 天内不得重复打扰）

## 步骤

1. **先定分层**，用本店真实复购周期：
   - 沉默 1~1.5 个周期 → 轻度流失：温和提醒
   - 1.5~3 个周期 → 中度流失：给一个**具体的**回来理由
   - 3 个周期以上 → 重度流失：低打扰、高价值的一次性唤醒
2. 按**价值 × 可挽回性**排序，优先处理「高价值 + 中度流失」—— 这档回收率最高。
3. 逐人写文案，必须包含至少一个**个人化锚点**（常点的菜、上次到店时间、备注过的偏好）。
   - 禁止只把姓名插进模板；没有个人化锚点就不发。
4. 给出**外发节奏**：每天限流多少条、间隔多久，避免一次性打扰全部名单。
5. 给出**回收判定口径**：发出后多少天内到店算召回成功，口径要事先定好。

## 输出格式

- 分层表：层级 / 人数 / 客单均值 / 建议动作
- 每人一条的文案清单（客户 / 锚点 / 文案 / 建议发送时间）
- 一个「本周先发这 20 个」的起步批次（不要一次全发）

## 边界

- **不使用虚假紧迫感**（"最后一天"这类）和不存在的优惠；给出的权益必须是老板能兑现的。
- 外发前必须经**审批**；本技能只产出草稿与批次计划。
- 不编造客户数据。缺偏好信息时，用「上次消费时间 + 常点品类」作为锚点。
